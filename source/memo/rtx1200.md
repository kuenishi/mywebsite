## Firmware Update

モノはこれ

```
$ md5sum firmware/rtx1200.bin
b16f4275d5da4a3b00251fcec6e51ad7  firmware/rtx1200.bin
cat firmware/rtx1200.md5
b16f4275d5da4a3b00251fcec6e51ad7 *rtx1200.bin
```

TFTPで送る

受け取り側の用意

```
# tftp host any
```

これは一見やばい感じだがどこにもつながってない場合はこれでOK.
運用中の場合は `any` をソースIPで置き換えればよし

c.f. https://qiita.com/kosuge/items/d299d60d2ecf03f3ed13


```
$ atftp --verbose -p -l firmware/rtx1200.bin  192.168.100.1 69
Verbose mode on.
tftp: error received from server <Access violation>
tftp: aborting
```

とするが、これは失敗。理由はリモートファイル名が設定されていないから。

```
$ atftp 192.168.100.1
tftp> put
Usage: put local_file [remote_file]
tftp> put firmware/rtx1200.bin
tftp: error received from server <Access violation>
tftp: aborting
tftp> put firmware/rtx1200.bin exec
timeout: retrying ...
timeout: retrying ...
timeout: retrying ...
timeout: retrying ...
timeout: retrying ...
timeout: retrying ...
tftp: aborting
```

マニュアルに `exec` と書いてある意味がわからなかったが、これを destination にするとこれを実行するという意味のようだ。
スイッチ側のコンソールはこういう感じになる

```
Update exec file receiving... Testing received file... Writing to Nonvolatile memory...
#
#
#  done
Restarting ...
Connection closed by foreign host.
```

他にもマニュアルには注意事項が書かれている。

> 転送したファームウェアを不揮発性メモリに書き込んでいる間、ランプが交互に点灯します。不揮発性メモリに書き込まれると、自動的に再起動します。
> 外部メモリ上のファームウェアで動作している場合には、ファイル名を指定しない限り外部メモリのファームウェアが変更されます。
> 不揮発性メモリに書き込む時間が長いため、TFTP クライアントがタイムアウトする場合がありますが、正常にリビジョンアップできます。
